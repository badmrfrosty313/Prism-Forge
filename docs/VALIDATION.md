# Validation record

## Cloud build environment (local to this Codex task)

- Debian 13 x86-64, GCC 14.2.0, CMake 4.4.4. Builds were limited to two parallel jobs.
- Debug: strict-warning configure/build passed; CTest passed 2/2 test targets; `prismforge_tests` reported 65 assertions.
- Release: strict-warning configure/build passed; CTest passed 2/2 test targets; `prismforge_tests` reported 65 assertions.
- AddressSanitizer + UndefinedBehaviorSanitizer Debug build: configure/build passed; CTest passed 2/2 test targets.
- The unit assertions cover P3/P6 parsing, comments, CRLF and whitespace-valued P6 raster starts, malformed/truncated data, invalid/maxval/range checks, dimensions and pixel bounds, encoded-size limits for PPM and codec inputs, filter reference values and parameters, alpha preservation, resize interpolation, ordered pipelines, PNG exact RGBA roundtrip, JPEG tolerance, cross-format conversion, corrupt/unsupported inputs, and codec errors.
- CLI CTest exercises a 3×3 PPM/PNG/JPEG input-output conversion grid, pipeline and legacy syntax, invalid arguments, image decode failure, batch behavior, unsupported files, directory overlap, overwrite protection, and output signatures.
- The gallery PPM filter results in `examples/outputs/` and PNG previews in `examples/previews/` were generated by the built Prism-Forge executable; each preview was encoded from its corresponding genuine P6 result. `file` verified PNG signatures and dimensions (96×64 except the 64×48 resize output).
- Release benchmark, 128×96 and three repetitions, emitted seven CSV rows with nonzero checksums: Gaussian blur, Sobel, color adjustment, grayscale, sharpen, bilinear resize, and a blur/grayscale/sharpen pipeline. FNV-1a covers dimensions and RGBA bytes; hashing occurs outside the measured filter interval and a volatile sink consumes each checksum. The observed times are environment-specific and are not CI thresholds.

These checks validate the current Codex workspace only. GitHub Actions results, artifact links, package smoke tests, and Windows validation will be recorded here only after the release-candidate branch workflow completes successfully.

## Known validation limits

The Linux binary targets the Ubuntu 22.04/glibc 2.35 baseline. Windows validation is performed by GitHub-hosted runners. stb is pinned and limited to PNG/JPEG but is not independently security-audited. EXIF orientation, ICC profile handling, and color management are unsupported. JPEG encoding is lossy. No performance threshold is enforced.
